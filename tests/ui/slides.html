Tổng Quan Hệ Thống (ECM Project)

02/12

Nghiệp Vụ Cốt Lõi

  • Thương mại điện tử: Tìm kiếm, giỏ hàng động, tự động gộp giỏ hàng vãng lai sau đăng nhập, áp dụng mã giảm giá (coupon).
  • PC Builder: Lắp ráp linh kiện máy tính, tự động kiểm tra tương thích Socket CPU/Mainboard, chuẩn RAM và công suất nguồn điện (PSU).
  • Thanh toán VietQR: Tạo mã QR động tự động, tích hợp Webhook phản hồi trạng thái thanh toán thành công (IPN).
  • Bảo hành & RMA: Quản lý số Serial, hạn bảo hành, quy trình đổi trả hàng lỗi đa trạng thái (RMA).

Phân Quyền Vận Hành

Khách Hàng (Customer)
Nhân Viên (Staff)
Quản Trị Viên (Admin)
Ảnh sơ đồ: Phân quyền truy cập và vai trò người dùng trong hệ thống

Hệ thống phân quyền chi tiết dựa trên Token cá nhân (Laravel Sanctum) và Middleware quản lý tài nguyên nghiêm ngặt ở API Backend.

ECM Project là hệ thống e-commerce bán linh kiện máy tính, điểm đặc trưng là bộ PC Builder kiểm tra tương thích phần cứng, cổng thanh toán VietQR quét mã QR, và phân hệ bảo hành RMA. Hệ thống vận hành dựa trên 3 vai trò: Customer, Staff, Admin.

Mục Tiêu & Phạm Vi Kiểm Thử

04/12

Phạm Vi Thực Hiện (In-Scope)

  • Unit Test: Kiểm tra logic tính thuế VAT, phí vận chuyển cước, áp dụng coupon và đối khớp linh kiện PC Builder cô lập.
  • Feature / API Test: Kiểm tra tính hợp lệ dữ liệu đầu vào (Validation Rules), phân quyền người dùng API, và DB transactions.
  • E2E UI Test: Giả lập toàn bộ hành trình mua sắm và dựng PC của người dùng trên browser qua Playwright.
  • Postman API Test: Tự động hóa kiểm thử tích hợp hộp đen bằng Collection Runner.

Ngoài Phạm Vi (Out-of-Scope)

  • Kiểm thử bảo mật hạ tầng mạng, chống tấn công DDoS quy mô lớn.
  • Kết nối API thực tế với các đơn vị giao vận thứ ba (GHN, GHTK...) và ngân hàng.
  • Hệ thống thực hiện giả lập (Mocking) hoặc dùng sandbox/stub để đối chiếu kết quả thanh toán.
Về phạm vi kiểm thử, nhóm tập trung sâu vào Unit Test các thuật toán độc lập, Feature API Test các API Laravel, E2E UI Test với Playwright và API Suite. Các phần bảo mật mạng hoặc cổng thanh toán thật, vận chuyển thật nằm ngoài phạm vi và được mock.

Kiểm Thử Hộp Trắng (Unit Tests)

06/12

Domain Calculators Logic

  • ShoppingCart: Kiểm tra các hàm thêm/sửa/xóa sản phẩm, tự động cộng dồn số lượng khi trùng sản phẩm.
  • ShippingCalculator: Tính phí vận chuyển theo cân nặng thực tế (làm tròn lên kg) và vùng giao hàng. Miễn phí ship khi đạt ngưỡng đơn hàng.
  • TaxCalculator: Tính đúng thuế suất VAT dựa trên điểm cơ bản (basis points) và làm tròn lên toán học.
  • CouponApplicator: Áp dụng giảm giá và khống chế giới hạn giảm tối đa bằng tổng tiền đơn hàng, chặn coupon nếu chưa đạt giá trị đơn tối thiểu.

PC Builder & State Machines

  • Socket Compatibility: CPU Intel LGA1700 ghép với Mainboard AM5 phải ném lỗi không tương thích.
  • RAM Type Match: Chặn việc cắm RAM DDR4 vào khe cắm RAM DDR5 trên Mainboard.
  • PSU Wattage Check: Tính tổng công suất TDP tối đa của cấu hình + 50W mặc định, nhân 1.2 dung sai dự phòng. Nguồn PSU phải đáp ứng ngưỡng này.
  • Order & RMA State Machines: Đảm bảo đơn hàng đi đúng vòng đời trạng thái và chặn các bước chuyển đổi phi logic (ví dụ: RMA chuyển thẳng từ Pending sang Refunded).
Kiểm thử hộp trắng tập trung vào logic tính toán cô lập ở backend: từ giỏ hàng, phí ship làm tròn kg, thuế, coupon, đến độ tương thích phần cứng của PC Builder (socket, loại RAM, công suất PSU vượt ngưỡng 20% dung sai), và vòng đời trạng thái đơn hàng/RMA.

Kiểm Thử Hộp Đen (Feature & Integration)

07/12

Xác Thực & Phân Quyền

  • Sanctum Auth API: Đăng ký tài khoản (cấp Sanctum token), Đăng nhập (verify bcrypt hash), Đăng xuất (thu hồi token trong bảng personal_access_tokens).
  • Access Control: Phân quyền nghiêm ngặt, chặn staff và customer CRUD sản phẩm của Admin (trả lỗi 403 Forbidden).
  • Cart Merging: Tự động gộp giỏ hàng tạm vãng lai (guest_token UUID) sang tài khoản người dùng chính thức ngay sau khi đăng nhập thành công.

Checkout & Thanh Toán VietQR

  • Database Transaction: Checkout đơn hàng bao bọc bởi Transaction. Khóa dòng dữ liệu tồn kho bằng lockForUpdate() (Lock bi quan) để tránh race condition bán quá số lượng.
  • VietQR Webhook Checksum: Webhook POST nhận thông tin chuyển khoản phải xác thực chữ ký HMAC SHA256 với Secret Key. Giao dịch sai key bị chặn 401.
  • Idempotency: Tra cứu bảng processed_webhook_events để chống xử lý trùng lặp giao dịch khi webhook gửi lặp.
Ảnh chụp giao diện: Mã QR VietQR động hiển thị lúc checkout và Webhook đối soát IPN
Kiểm thử hộp đen kiểm tra tích hợp API: Hệ thống xác thực Sanctum, phân quyền người dùng, tự động gộp giỏ hàng khi đăng nhập. Đặc biệt, luồng checkout dùng lockForUpdate để chặn Race Condition, webhook VietQR dùng HMAC SHA256 và Idempotent để chống xử lý trùng.

Kiểm Thử Giao Diện E2E (Playwright)

08/12

Kịch Bản E2E Trình Duyệt

  • Hành trình mua hàng đầy đủ: Giả lập người dùng đăng ký -> Đăng nhập -> Tìm kiếm sản phẩm -> Lắp ráp cấu hình PC Builder tương thích -> Thêm vào giỏ -> Điền thông tin giao hàng -> Checkout đơn hàng -> Kiểm tra mã QR.
  • Quy trình bảo hành RMA: Giả lập khách hàng tạo yêu cầu đổi trả linh kiện lỗi -> Đăng nhập tài khoản Staff phê duyệt -> Kiểm tra tồn kho kho hàng tự động cộng trả lại.
  • Hiệu năng UI: Đánh giá thời gian tải trang SPA (Vue 3) dưới 1.0 giây và hiển thị Responsive.
Ảnh chụp giao diện: Trang dựng cấu hình máy tính PC Builder của ECM Project

Phân Loại Lỗi (Defect Levels)

Cấp độ Nghiêm trọng Ví dụ phát hiện
Level 1 Blocker Sập database, lỗi build compiler.
Level 2 Critical Sai tổng tiền, lỗi thanh toán webhook.
Level 3 Major Wishlist lỗi, giao diện bị chậm.
Level 4 Minor Sai font chữ, lệch margin, chính tả.

Các Lỗi Phát Hiện & Khắc Phục

  • Bug 01: Thiếu dữ liệu Seeder (Critical)
    Mô tả: Chạy Playwright bị 401/404 liên tục do thiếu tài khoản mặc định.
    Khắc phục: Cập nhật DatabaseSeeder tự động nạp UserRoleSeeder để khởi tạo các tài khoản test.
  • Bug 02: Playwright API Timeout (Major)
    Mô tả: Chạy tuần tự hơn 50 API tốn 110s, vượt quá timeout 90s mặc định của Playwright.
    Khắc phục: Tăng timeout test lên 300,000ms (5 phút) và locator lên 240,000ms.
Ảnh chụp màn hình: Log lỗi timeout của Playwright API suite khi chưa fix
Hệ thống defect tracking định nghĩa 4 mức độ lỗi từ Blocker đến Minor. Trong quá trình chạy thử nghiệm, nhóm đã phát hiện và vá thành công 2 lỗi lớn: Lỗi thiếu seeder tài khoản test dẫn đến lỗi 401, và lỗi timeout khi chạy API test suite trên Playwright.

Đánh Giá Quy Trình & Kết Luận

12/12

Ưu Điểm Quy Trình QA

  • Độ bao phủ cao (High Coverage): Kết hợp chặt chẽ giữa Unit Test (logic nghiệp vụ), Feature Test (tích hợp API, bảo mật) và Playwright UI E2E.
  • Tính độc lập & Tốc độ: Ứng dụng kỹ thuật Mocking (như Notification::fake(), Event::fake()) giúp chạy test độc lập không phụ thuộc SMTP và bên thứ ba.
  • Bảo mật vững vàng: Viết test bảo vệ chặt chẽ webhook HMAC SHA256 và rate limits tránh tấn công Brute-force.

Vai Trò Của AI Hỗ Trợ

  • Tăng tốc thiết kế test: Generator tự động sinh dữ liệu test case (phân vùng tương đương, giá trị biên) giúp tiết kiệm thời gian viết tay.
  • Cải thiện chất lượng: RAG scan mã nguồn bảo đảm testcase luôn bám sát theo các ràng buộc Validation thay đổi trong code Laravel.
  • Đúc kết: Kiểm thử tự động giúp rút ngắn thời gian bàn giao và giảm thiểu tối đa lỗi Regression của dự án.
Về ưu điểm, quy trình QA đạt độ bao phủ cao và tốc độ chạy test nhanh nhờ SQLite in-memory và Mocking. AI RAG đóng vai trò then chốt giúp sinh nhanh test case biên và validate dữ liệu. Kết luận kiểm thử tự động là cốt lõi cho chất lượng phần mềm.
